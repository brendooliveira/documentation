Um cartão guardado deixa a segunda compra acontecer num toque. Você cobra citando um código `pm_`, e
o comprador não redigita número, validade nem CVV.

## Como um cartão entra

De dois jeitos, e o primeiro é o melhor sempre que existir.

### Na venda, com `save_card`

Como efeito de uma **venda aprovada** em que alguém pediu para guardar:

```json Ao criar a cobrança
{ "amount": 10000, "save_card": true }
```

Uma cobrança recusada não guarda nada. Se o cofre falhar por qualquer motivo, a venda segue
aprovada: guardar um cartão nunca pode derrubar um pagamento que já deu certo.

Prefira este caminho. A cobrança aprovada é a prova de que aquele cartão era mesmo do comprador, e
essa prova aparece depois na taxa de aprovação das cobranças seguintes.

### Sem cobrar, com [`POST /v1/cards`](/api-reference/cartoes/guardar)

Para quando não há primeira venda: assinatura com teste grátis, cobrança adiada, upsell combinado
antes de qualquer cobrança.

```json
{
  "customer": { "name": "Ana P Souza", "email": "ana@exemplo.com.br", "document": "11144477735", "phone_ddd": "11", "phone_number": "987654321" },
  "card": { "token": "token_...", "holder_name": "ANA P SOUZA", "billing_address": { "…": "…" } }
}
```

Ao guardar, pedimos ao provedor uma **verificação sem valor**: ele consulta a bandeira e o emissor
para saber se o cartão existe e pode transacionar, sem tocar no limite do comprador. Falhando, nada
é guardado.

<Warning>
  Essa verificação é menos que uma autorização, e a diferença é real: um cartão guardado por aqui
  passou por uma consulta, não por uma venda. É por isso que esta rota tem um **limite de chamadas
  bem mais apertado** que o resto da API — a mesma consulta que valida um cartão legítimo serve para
  descobrir, de graça, se um número roubado está vivo. Vinte por minuto cobrem o uso real; quem
  precisa migrar uma base grande [fala com a gente](mailto:suporte@usevext.com) antes.
</Warning>

O mesmo plástico guardado de novo devolve o **mesmo** `pm_` — não cria um segundo.

## Como cobrar com ele

Em `POST /v1/charges`, troque o `token` pelo `id`:

```json
{
  "amount": 10000,
  "payment_method": "credit_card",
  "items": [{ "description": "Curso completo", "quantity": 1, "amount": 10000 }],
  "card": { "id": "pm_01k1y6r6m6q2x0p3d9v4t7c8n2", "installments": 1 }
}
```

`card.id` e `save_card` não convivem na mesma cobrança: um cartão que já está no cofre não entra
nele de novo.

## Consultar e remover

Os três endpoints pedem o escopo `cards:manage`:

| Operação | Endpoint |
| --- | --- |
| [Listar](/api-reference/cartoes/listar) | `GET /v1/cards` |
| [Consultar](/api-reference/cartoes/consultar) | `GET /v1/cards/{code}` |
| [Remover](/api-reference/cartoes/remover) | `DELETE /v1/cards/{code}` |

A listagem filtra por `customer_document`, que é como você encontra os cartões de um comprador
específico. Cartões vencidos ficam de fora por padrão; `include_expired=true` os traz de volta.

**Remover revoga, não apaga.** O cartão deixa de poder ser cobrado na hora, e o registro continua
existindo — é o que permite responder "com que cartão foi aquela cobrança de março" um ano depois.
Apagar a linha deixaria a sua conciliação com um buraco justamente nas vendas que alguém contestou.

<Note>
  `last_four` e `brand` são para exibir, nunca para reconhecer. Dois cartões do mesmo comprador
  podem terminar nos mesmos quatro dígitos, e a bandeira que precifica a parcela é detectada pelo
  BIN antes da autorização. O que identifica um cartão é o `pm_`.
</Note>

## O que dá errado

| `code` | HTTP | O sintoma |
| --- | --- | --- |
| `card_not_found` | `404` | O `pm_` não existe, ou é de outra conta |
| `card_expired` | `422` | A validade passou |
| `card_revoked` | `422` | O cartão foi removido |
| `card_not_usable_on_account` | `422` | O cartão não vale na conta que está cobrando |
| `one_click_requires_three_ds` | `403` | Você pediu `three_d_secure: "required"` num cartão guardado, que [não pode autenticar](/essenciais/autenticacao-do-portador) |
| `insufficient_scope` | `403` | A chave não tem `cards:manage` |

<Warning>
  A referência guardada pertence à conta do adquirente que a criou. Trocar a conta da sua loja
  invalida todos os cartões do cofre de uma vez, e as recompras passam a ser recusadas com uma
  mensagem genérica da operadora — que se parece com cartão sem limite. Antes de trocar de conta,
  conte com os compradores tendo de digitar o cartão outra vez.
</Warning>
