O Elements entrega os quatro campos do cartão e mais nada. Ele fica no meio do **seu** formulário,
com o seu botão e o seu layout, e o que devolve é um `token` de uso único — a cobrança quem cria é
você, com a chave secreta, no seu servidor.

Escolha esta forma quando o checkout já existe e você precisa trocar só o pedaço do cartão. Se o
que você quer é o checkout inteiro, com Pix, parcelas e endereço, o [Drop-in](/embed/drop-in) faz
tudo isso sem código seu.

<Steps>

<Step title="Monte os campos">

```html
<form id="checkout">
  <input name="nome" placeholder="Nome completo" />
  <input name="email" type="email" placeholder="E-mail" />

  <div id="cartao"></div>

  <button type="submit" disabled>Pagar R$ 100,00</button>
</form>

<script src="https://api.usevext.com/v1/vext.js"></script>
<script>
  const vext = Vext('pk_live_...');
  const cartao = vext.elements({ theme: 'light' }).create('card');

  cartao.mount('#cartao');

  cartao.on('change', ({ complete, brand, error }) => {
    document.querySelector('button').disabled = !complete;
  });
</script>
```

O evento `change` é o que liga o seu botão. Ele traz `complete`, `empty`, `brand` e `error` a cada
tecla, e `brand` é a bandeira detectada pelo BIN — útil para acender o ícone certo.

</Step>

<Step title="Peça o token no envio">

```javascript
document.querySelector('#checkout').addEventListener('submit', async (evento) => {
  evento.preventDefault();

  const { token, brand, lastFour, threeDs, deviceEventId } = await cartao.createToken({
    holderName: 'ANA P SOUZA',
    amountCents: 10000,              // obrigatório quando houver 3DS
    installments: 1,
    customer: {
      name: 'Ana Paula Souza',
      email: 'ana@exemplo.com',
      document: '39053344705',       // só dígitos
      phone: '11987654321',          // DDD + número
    },
    billingAddress: {
      zip_code: '01310100',
      street: 'Avenida Paulista',
      number: '1000',
      neighborhood: 'Bela Vista',
      city: 'São Paulo',
      state: 'SP',
    },
  });

  await fetch('/meu-backend/pagar', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ token, brand, threeDs, deviceEventId, pedido: 1042 }),
  });
});
```

O token vale para **uma** cobrança e vence em cerca de um minuto. Peça-o no envio do formulário, e
não quando o quadro monta: emitido cedo, ele chega morto no servidor de quem demorou preenchendo o
endereço.

`deviceEventId` vem `null` com frequência — bloqueadores de anúncio derrubam a coleta. Isso é
normal e não deve impedir a venda; mande adiante o que vier.

</Step>

<Step title="Cobre no seu servidor">

```php
$cobranca = Http::withToken(config('services.vext.key'))
    ->withHeaders(['Idempotency-Key' => $pedido->chave_idempotencia])
    ->post('https://api.usevext.com/v1/charges', [
        'amount' => 10000,
        'payment_method' => 'credit_card',
        'description' => 'Pedido 1042',
        'reference' => 'pedido-1042',
        'customer_ip' => $request->ip(),
        'device_event_id' => $request->input('deviceEventId'),
        'customer' => [/* ... */],
        'items' => [/* ... */],
        'card' => [
            'token' => $request->input('token'),
            'installments' => 1,
            'holder_name' => 'ANA P SOUZA',
            'brand' => $request->input('brand'),
            'billing_address' => [
                'zip_code' => '01310100',
                'street' => 'Avenida Paulista',
                'number' => '1000',
                'neighborhood' => 'Bela Vista',
                'city' => 'São Paulo',
                'state' => 'SP',
            ],
            'three_ds' => $request->input('threeDs'),   // null quando não houve
        ],
    ]);
```

Repasse `three_ds` exatamente como veio do navegador. É esse par `transaction_id` + `status` que
carrega a transferência de responsabilidade numa contestação; perdê-lo no caminho significa
autenticar o portador e pagar o prejuízo assim mesmo.

</Step>

</Steps>

## Autenticação do portador no Elements

O quadro cuida do desafio sozinho, inclusive da tela em que o banco pede a senha — ele se expande
sobre a sua página e volta ao tamanho normal quando termina. O que você precisa fazer é **mandar os
dados**: sem `amountCents`, `customer` e `billingAddress` no `createToken`, a autenticação não tem
como acontecer e a chamada falha com `three_ds_data_missing`, nomeando o campo que faltou.

Se a sua loja tem a autenticação ligada, esses três campos deixam de ser opcionais. Ver
[Autenticação do portador](/essenciais/autenticacao-do-portador).

## O que o Elements não faz

Vale saber antes de começar, para você não procurar o que não existe:

- **Não tem Pix.** O quadro é de cartão. O Pix continua em `POST /v1/charges` com
  `payment_method: pix`, ou no [Drop-in](/embed/drop-in), que mostra os dois lado a lado.
- **Não tem cofre nem Vext Link.** Pagar com um cartão guardado exige a sessão de checkout, porque é
  no servidor que sabemos de quem é o cartão. Ver [Vext Link](/embed/vext-link).
- **Não tem grade de parcelas.** Você desenha o seletor; os valores vêm de
  [`GET /v1/installments`](/api-reference/cobrancas/parcelas), que devolve a matriz por bandeira com
  juros já calculados.
- **Não tem endereço de cobrança.** Os campos são seus; o quadro só repassa o que você passou em
  `billingAddress`. Para preencher por CEP, o Drop-in já faz isso.

## Erros que vêm do quadro

| `code` | Quando aparece |
| --- | --- |
| `card_invalid` | Número, validade ou CVV que não passam na validação local |
| `holder_name_missing` | Nem `holderName` nem `customer.name` foram informados |
| `card_unavailable` | A loja não está habilitada a cobrar no cartão |
| `three_ds_data_missing` | Falta `amountCents`, `customer` ou `billingAddress` — a mensagem diz qual |
| `three_ds_failed` | A autenticação não completou |
| `tokenization_failed` | O provedor recusou os dados do cartão |
| `not_mounted` | `createToken()` antes de `mount()` |
| `not_ready` | `createToken()` antes do evento `ready` |
