O Drop-in entrega o checkout pronto: as abas de cartão e Pix, a grade de parcelas, o endereço de
cobrança, a autenticação do portador e o botão de pagar. Você abre uma sessão no seu servidor,
entrega o `client_secret` ao navegador e recebe a cobrança já autorizada.

<Note>
  Esta página descreve o modo com **sessão aberta antes**, que é o mais completo: é ele que tem
  Vext Link, cartão guardado e compra de um clique. O preço é o valor ficar congelado desde a
  montagem — se o seu checkout tem order bump, cupom ou frete que muda na tela, vá para o
  [Drop-in diferido](/embed/drop-in-diferido).
</Note>

<Step title="Abra a sessão no seu servidor">

A sessão congela o que está sendo vendido: valor, itens, formas de pagamento e teto de parcelas.
Depois de aberta ela **não muda de valor** — e é isso que faz o `amount` que o navegador enviar ser
ignorado.

<NotaIdempotencia />

<CodeGroup>

```bash cURL
curl https://api.usevext.com/v1/checkout_sessions \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: 8f1c2b7a-0f3e-4c1d-9b6a-2e5d7c4a1f80" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 10000,
    "description": "Pedido 1042",
    "reference": "pedido-1042",
    "max_installments": 6,
    "items": [
      { "code": "SKU-7", "description": "Curso completo", "quantity": 1, "amount": 10000 }
    ]
  }'
```

```php PHP
$pedido->update(['chave_idempotencia' => (string) Str::uuid()]);

$sessao = Http::withToken(config('services.vext.key'))
    ->withHeaders(['Idempotency-Key' => $pedido->chave_idempotencia])
    ->post('https://api.usevext.com/v1/checkout_sessions', [
        'amount' => $pedido->total_em_centavos,   // inteiro, sempre
        'description' => $pedido->descricao,
        'reference' => "pedido-{$pedido->id}",
        'max_installments' => 6,
        'items' => $pedido->itens->map(fn ($item) => [
            'code' => $item->sku,
            'description' => $item->nome,
            'quantity' => $item->quantidade,
            'amount' => $item->preco_unitario_em_centavos,
        ])->all(),
        'customer' => [                            // opcional: preenche o formulário
            'name' => $pedido->cliente->nome,
            'email' => $pedido->cliente->email,
        ],
    ])->json();

$pedido->update(['sessao_id' => $sessao['id']]);

return view('checkout', ['clientSecret' => $sessao['client_secret']]);
```

```javascript JavaScript
pedido.chaveIdempotencia ??= crypto.randomUUID();
await pedido.save();

const resposta = await fetch('https://api.usevext.com/v1/checkout_sessions', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${process.env.VEXT_API_KEY}`,
    'Idempotency-Key': pedido.chaveIdempotencia,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    amount: pedido.totalEmCentavos, // inteiro, sempre
    description: pedido.descricao,
    reference: `pedido-${pedido.id}`,
    max_installments: 6,
    items: pedido.itens.map((item) => ({
      code: item.sku,
      description: item.nome,
      quantity: item.quantidade,
      amount: item.precoUnitarioEmCentavos,
    })),
  }),
});

const sessao = await resposta.json();
pedido.sessaoId = sessao.id;
```


</CodeGroup>

A resposta traz o `client_secret`, no formato `cs_..._secret_...`. Ele volta **uma única vez**, na
criação: guardamos só um hash SHA-256 dele. Entregue-o à página e não o grave — uma sessão perdida
se resolve abrindo outra, e o que não existe no seu banco não vaza dele.

Ver [Abrir sessão de checkout](/api-reference/checkout/criar) para a lista completa de campos.

</Step>

<Step title="Monte o quadro na página">

```html
<div id="pagamento"></div>

<script src="https://api.usevext.com/v1/vext.js"></script>
<script>
  const vext = Vext('pk_live_...');

  const checkout = vext.checkout({
    clientSecret: 'cs_01k1y6r6m6q2x0p3d9v4t7c8n2_secret_...',
  });

  checkout.mount('#pagamento');
</script>
```

Três linhas, e o quadro se vira sozinho: lê a sessão, desenha as formas de pagamento que sobraram
disponíveis, calcula as parcelas e ajusta a própria altura.

<Frame caption="A aba Pix do mesmo quadro. O código é gerado na confirmação, e não na abertura.">
  <img src="/images/embed/pix.png" alt="Aba Pix selecionada, com os campos de identificação do comprador e o botão de gerar o código" />
</Frame>

O `client_secret` viaja no **fragmento** da URL do iframe, aquele pedaço depois do `#`. Fragmento
não é enviado ao servidor, não entra em log de acesso e não vaza pelo `Referer`.

</Step>

<Step title="Libere no charge.paid, não no evento do navegador">

<Warning>
  O evento `pending` **não é pagamento**. Ele significa que o código Pix foi criado e está na tela.
  Uma página que libera o produto ali libera antes de receber. Quem confirma dinheiro é o webhook
  [`charge.paid`](/api-reference/webhooks/charge-paid), e ele vale para o cartão também.
</Warning>

```javascript
checkout.on('result', ({ id, status, method }) => {
  // Cartão aprovado. Mostre o recibo, mas confirme no seu backend.
  window.location.href = `/pedidos/${pedido}/obrigado?cobranca=${id}`;
});

checkout.on('pending', ({ id, method }) => {
  // Pix gerado, ninguém pagou ainda. Mostre "aguardando pagamento".
});

checkout.on('error', (erro) => {
  console.error(erro.code, erro.message);
});
```

O quadro acompanha o Pix sozinho e emite `result` quando o pagamento cai, sem você programar
polling. Ainda assim, a liberação do produto acontece no webhook: a aba pode ser fechada no segundo
seguinte ao pagamento, e aí o `result` nunca chega a ninguém.

</Step>

</Steps>

## Desenhar o seu próprio botão

Passe `submitButton: false` e o quadro entrega só os campos. O pagamento passa a ser disparado por
você, com `confirm()`:

```javascript
const checkout = vext.checkout({
  clientSecret: '...',
  submitButton: false,
});

checkout.mount('#pagamento');

let pronto = false;
checkout.on('change', ({ complete }) => {
  pronto = complete;
  document.querySelector('#pagar').disabled = !complete;
});

document.querySelector('#pagar').addEventListener('click', async () => {
  try {
    const cobranca = await checkout.confirm();
    // cartão: já aprovada. pix: pending, com o código na tela.
  } catch (erro) {
    // card_declined, pix_failed, not_ready, destroyed...
  }
});
```

Duas coisas que economizam um chamado:

- **Erro de campo não rejeita a promessa.** Cartão inválido, CEP faltando ou CVV curto aparecem
  junto do campo, dentro do quadro, e a `Promise` continua pendente esperando o comprador corrigir.
  Um `catch` que desabilita o botão para sempre travaria a venda num erro que o comprador já
  consertou.

  <Frame caption="A recusa de campo fica no campo, e não chega ao seu código.">
    <img src="/images/embed/erro-de-campo.png" alt="Formulário com o número do cartão e a validade destacados em vermelho, cada um com a sua mensagem" />
  </Frame>

- **Os eventos continuam disparando.** `result` e `pending` são emitidos mesmo com botão próprio, o
  que mantém o seu pixel e a sua analytics funcionando sem duplicar código.

## O que a sessão garante

<AccordionGroup>

<Accordion title="Uma sessão, uma cobrança" icon="lock">
  Confirmar duas vezes não cria duas cobranças. A segunda chamada devolve a **mesma** cobrança, e
  isso é garantido no banco, não na aplicação — um duplo clique ou um `retry` do navegador não viram
  dois débitos no cartão do comprador.
</Accordion>

<Accordion title="O valor vem da sessão, nunca do navegador" icon="shield">
  `amount`, `items`, `reference` e `metadata` são lidos da sessão no momento de cobrar. Mandar
  `amount: 1` no corpo do `confirm` não muda nada — o campo é ignorado. É o que impede que alguém
  com o console aberto compre por um centavo.
</Accordion>

<Accordion title="Três tentativas por minuto" icon="gauge">
  Cada sessão aceita três confirmações por minuto. Abrir uma sessão nova exige a sua chave secreta,
  então o embed não serve para testar cartões roubados em série. Passando disso, a resposta é `429`.
</Accordion>

<Accordion title="Trinta minutos, e o comprador recomeça" icon="timer">
  Uma sessão vive `1800` segundos por padrão, de `300` a `86400`. Vencida, o `confirm` responde
  `422` com a mensagem pedindo para recarregar a página. Abra outra sessão — a antiga não volta.
</Accordion>

</AccordionGroup>
